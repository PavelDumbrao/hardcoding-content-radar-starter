# Content Radar AI — стартер Hardcoding PRO

Сервис, который ищет вирусный контент, считает метрики роста и объясняет, почему
ролик сработал. Управление — через чат: пишешь запрос обычным текстом, получаешь
разбор с ссылками, цифрами и идеями.

Это **учебный стартовый проект**. Он рабочий, но намеренно не «докручен до конца»:
в `docs/next-steps.md` лежит карта, что именно шлифовать самому.

## Чем это отличается от «ещё одного чата с ИИ»

Здесь цифры считает код, а не модель. Разделение жёсткое:

| Кто | Что делает |
|---|---|
| ИИ-агент | Понимает запрос, ищет по смыслу, объясняет, почему сработало, предлагает идеи |
| Python-код | Считает просмотры, скорость роста, ускорение, outlier, свежесть, дедупликацию |

Модель физически не может придумать просмотры: у каждой цифры в ответе есть источник
и время замера (`observed_at`). Если ключа от площадки нет — сервис скажет об этом
прямо, а не нарисует красивые числа.

## Что уже работает

- Чат с рендером Markdown: списки, таблицы, цитаты, код, кнопка «Скопировать ответ».
- Агент с типизированными инструментами (PydanticAI) — он сам решает, что вызвать.
- Три источника по единому контракту: YouTube, VK, Instagram (через Apify).
- Хранение в PostgreSQL: видео, авторы, история замеров метрик, история запросов.
- Детерминированные метрики: `views_per_hour`, `acceleration`, `outlier`, `trend_score`.
- Прозрачность: в интерфейсе видно, какие шаги сделал агент и на какие данные опирался.
- Честная деградация: нет ключа — понятное сообщение вместо выдуманных данных.

## Что нужно для запуска

Установлен **Docker** (Docker Desktop на Mac или Docker Engine на сервере).
Больше ничего ставить не нужно: Python и база живут внутри контейнеров.

## Запуск за три шага

```bash
# 1. Скопируй настройки и впиши свои ключи
cp .env.example .env

# 2. Подними проект
docker compose up -d --build

# 3. Открой в браузере
open http://localhost:8000
```

Проверить, что сервис жив и какая модель подключена:

```bash
curl -s http://localhost:8000/healthz
curl -s http://localhost:8000/api/sources
```

## Какие ключи нужны и что будет без них

Проект стартует **и без ключей площадок** — просто честно скажет, что источники недоступны.
Это правильное поведение, а не поломка.

| Переменная | Где взять | Что даёт |
|---|---|---|
| `LLM_API_KEY` | OpenAI, OpenRouter или свой LiteLLM | Без неё чат не отвечает: нужна модель |
| `YOUTUBE_API_KEY` | Google Cloud Console → YouTube Data API v3 | Поиск видео, метрики, комментарии |
| `VK_ACCESS_TOKEN` | VK, токен пользователя с доступом к video | Поиск видео и клипов, комментарии |
| `APIFY_TOKEN` | Apify Console → API & Integrations | Instagram: посты, рилсы, комментарии |

Модель нужна любая, которая умеет **вызывать инструменты** (tool calling) — иначе агент
не сможет ходить в источники. Укажи её в `LLM_MODEL`, а адрес — в `LLM_BASE_URL`.

Аккуратно с бюджетом: Apify платный за результат. В проекте уже стоит потолок расходов
на один запуск (`APIFY_MAX_CHARGE_USD`), не убирай его бездумно.

## Как работать с агентом

1. Нажми **Use this template** и создай свою копию репозитория.
2. Открой проект в Codex, Claude Code или Cline.
3. Скажи агенту начать с `AGENTS.md`, `PROJECT.md` и `TASKS.md`.
4. Дальше агент сам ведёт ветки, коммиты, Pull Request и проверки.

Тебе не нужно помнить Git-команды. Но и «сделай красиво» не работает: ставь задачу
через результат — что должно работать и как ты это проверишь.

## Безопасность

- `.env` не попадает в git — это уже настроено в `.gitignore`.
- В репозитории нет ни одного ключа: проверка `scripts/validate_project.py` ищет секреты
  и запускается автоматически в GitHub Actions при каждом push и Pull Request.
- Ключи выдавай с минимальными правами и меняй их, если они где-то засветились.
