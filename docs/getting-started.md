# Первый запуск по шагам

Инструкция для человека. Ничего не нужно устанавливать, кроме Docker.

## Шаг 0. Что должно быть на машине

```bash
docker --version
docker compose version
```

Если команды не найдены — поставь Docker Desktop (Mac/Windows) или Docker Engine (Linux).
Всё остальное — Python, база данных — уже внутри контейнеров.

## Шаг 1. Копия проекта у себя

Нажми **Use this template** на странице репозитория и создай свою копию, затем склонируй её:

```bash
git clone <адрес-твоей-копии>
cd <папка-проекта>
```

Если предпочитаешь работать через ИИ-агента — попроси его сделать это сам: он умеет
работать с Git и GitHub через `gh`. Правила для него лежат в `AGENTS.md`.

## Шаг 2. Настройки

```bash
cp .env.example .env
```

Открой `.env` и заполни минимум одно — ключ модели:

```env
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=твой-ключ
LLM_MODEL=gpt-4o-mini
```

Модель должна уметь **вызывать инструменты** (tool calling). Если сомневаешься —
начни с `gpt-4o-mini`: он дешёвый и умеет то, что нужно.

Остальные ключи (`YOUTUBE_API_KEY`, `VK_ACCESS_TOKEN`, `APIFY_TOKEN`) можно добавить
позже: сервис запустится и без них.

## Шаг 3. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает несколько минут: скачиваются образ Python и база.

Проверь, что всё поднялось:

```bash
docker compose ps
# оба сервиса должны быть в состоянии running / healthy
```

## Шаг 4. Первая проверка

```bash
curl -s http://localhost:8000/healthz
```

Ожидаемый ответ примерно такой:

```json
{"status":"ok","app":"Content Radar AI","environment":"local","llm_configured":true,"model":"gpt-4o-mini"}
```

`llm_configured: true` — ключ модели подхватился. Если `false` — проверь `.env`.
Имя модели должно совпадать с тем, что реально доступно твоему провайдеру.

Теперь посмотри, какие источники подключены:

```bash
curl -s http://localhost:8000/api/sources
```

Ты увидишь честный отчёт: что готово, а для чего не хватает переменной. Это нормальное
состояние — так и должно быть, пока ты не добавил ключи площадок.

## Шаг 5. Открой чат

```
http://localhost:8000
```

Первый запрос, который стоит попробовать:

> Проверь, какие источники тебе доступны, и скажи честно, что ты можешь сейчас.

Агент должен ответить без выдуманных цифр и объяснить, чего не хватает. Если он
начал «придумывать» ролики — это баг, и его надо разбирать с агентом.

## Шаг 6. Подключи источник и повтори

Возьми любой доступный тебе ключ из таблицы в `README.md`, добавь в `.env` и перезапусти:

```bash
docker compose up -d --force-recreate api
```

Теперь спроси по-настоящему:

> Найди 10 роликов про AI-агентов за последний месяц и покажи самые быстрорастущие.

Что должно быть в ответе:

- ссылки на реальные видео;
- просмотры и скорость роста;
- время замера метрик (`observed_at`);
- отдельный блок со шагами агента и источниками.

## Полезные команды

```bash
docker compose logs -f api          # смотреть логи в реальном времени
docker compose restart api          # перезапустить сервис
docker compose down                 # остановить (данные в базе сохранятся)
docker compose down -v              # остановить и стереть базу (полный сброс)
docker compose exec db psql -U radar -d radar   # зайти в базу руками
```

Посмотреть, что уже лежит в базе:

```sql
select platform, count(*) from videos group by platform;
select source, operation, status, latency_ms from source_events order by id desc limit 10;
select id, status, left(query, 50) from research_runs order by id desc limit 5;
```

## Если не работает

**Порт 8000 занят.** Поменяй в `docker-compose.yml` строку
`"127.0.0.1:8000:8000"` на `"127.0.0.1:8010:8000"` и открывай `http://localhost:8010`.

**`llm_configured: false`.** Проверь, что файл называется именно `.env` и лежит рядом
с `docker-compose.yml`, а после правки ты сделал `docker compose up -d --force-recreate api`.

**Агент отвечает, но источники «не настроены».** Так и должно быть без ключей площадок.
Проверь `/api/sources` — там написано, какой переменной не хватает.

**Модель не вызывает инструменты.** Скорее всего она не поддерживает tool calling.
Смени модель в `LLM_MODEL`.

**Всё упало после правки.** Посмотри логи: `docker compose logs --tail 100 api`.
Ошибка почти всегда описана человеческим текстом.
